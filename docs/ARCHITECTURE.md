# Forge — архитектура и правила кода

Forge — **локальный** инструмент для индустрии в EVE Online. Считает точное количество
материалов и реальную стоимость постройки под конкретный чертёж с оптимальной разбивкой на
потоки, строит расписание, отчёты по стройкам и рекомендует, что выгоднее строить.
Один пользователь на одной машине, не SaaS.

Код и комментарии — на русском; интерфейс — русский и английский (см. «Язык интерфейса»).

## Правила

На эти номера ссылаются комментарии в коде («правило 1», «правило 4»…).

1. **Вся математика локальная.** Сеть допустима ТОЛЬКО в `ingest` и `sync`. Модули `core`,
   `recommend`, `planner` не делают сетевых вызовов — читают из БД через `storage`.
2. **Формулу стоимости джоба реализуем сами**, не дёргаем онлайн-API в расчётах.
   everef — только опциональная сверка.
3. **Идемпотентный sync**: upsert без дублей; уважать ESI cache-заголовки и exponential
   backoff на error limit (HTTP 420); пагинация для структурного рынка и ассетов.
4. **ME-округление считается на каждый джоб отдельно** (ceil), не на суммарный прогон —
   поэтому разбивка на потоки меняет итоговое количество материалов.
5. **Секреты не в git.** Refresh-токены EVE SSO — в хранилище учётных данных ОС (`keyring`,
   в Windows — Диспетчер учётных данных), не в БД и не в `forge.toml`.
6. **Схема БД** — `docs/schema.sql` (сейчас v6), меняется только миграцией
   (`forge/storage/migrations.py`) с тестом.
7. Смена стека — отдельное решение, не попутная правка.
8. **Не прибивать решения игрока в коде.** Хабы, места, склад, роли, запреты, фильтры, пороги —
   в конфиг (`forge.toml`) и в пульт; значение по умолчанию — нейтральное и разумное.

## Слои

Пакеты под `forge/`. Слои строго однонаправленные, импорт только «вниз»:

```
sync → ingest → storage ← core ← (recommend, planner) ← web.service ← (desktop, web.app, interface)
                          ↑
                       config          i18n — лист без зависимостей, доступен всем слоям
```

- `storage` — модели, репозитории, миграции (SQLite). Без бизнес-логики. Единственная точка доступа к БД.
- `ingest` — внешние данные → БД через `storage`. Подмодули: `sde`, `market`, `industry`, `character`.
  ТОЛЬКО здесь и в `sync` разрешена сеть.
- `sync` — оркестрация `ingest` по таймерам.
- `core` — чистые расчёты: `bom`, `sourcing`, `cost`, `profit`. Читает через `storage`, без сети.
- `recommend` — ранжирование «что строить». Использует `core` + `storage`.
- `planner` — расписание «как строить»: разбивка по слотам и чарам во времени, цепочки реакций,
  данные для Gantt, шаги передачи BP между персонажами.
- `config` — чтение конфига (локации, структуры, роли чаров, freight, склад, рынок, планировщик,
  запреты, значения пульта). Read-only данные для `core`/`recommend`/`planner`.
- `core.locations` — справочник «система → станция/структура → контейнер» (без сети);
  `core.stock` — склад по настройке `[stock]` (партии помнят, где лежат).
- `web.service` — `ForgeService`: ВСЯ логика интерфейсов (расчёты корзины, отчёты, склад,
  настройки) в dict/list; `web.report` — отчёт по стройке; `web.app` — тонкий FastAPI (сервер
  HTML-отчётов + API).
- `desktop` — пульт PySide6 (основной интерфейс). `interface` — CLI (`forge ...`, в т.ч.
  `forge desktop`). Никто не импортирует `desktop`/`interface`.
- `i18n` — язык интерфейса (см. ниже).

`core`/`recommend`/`planner` НИКОГДА не импортируют `ingest`, `sync` или сеть; `ingest`
не импортирует `core` (нужное — своими запросами к БД, см. `ingest/character/structures.py`).

## Стек

- Python 3.12+, SQLite (без SQLite-специфики в репозиториях — чтобы можно было перенести на Postgres).
- `httpx` (ESI), `pydantic` (модели), `typer` (CLI), `pytest` (тесты), `ruff` + `mypy`.
- Пульт — **PySide6** (`forge/desktop`): Qt-шелл, тяжёлое — в фоновых потоках (`widgets.run_bg`),
  мутации Qt только в UI-потоке, `StatusHub` раз в 3 с, геометрия окна — в `.forge/desktop.ini`.
  Вид — в цветах EVE Online (`desktop/theme.py`: космос, cyan Photon #3fb8e0, золото Omega
  #e8a93a, уголки-скобы). HTML-отчёты отдаёт встроенный FastAPI на 127.0.0.1 (порт 8000–8010).
- Иконки — с EVE Image Server `https://images.evetech.net/types/{type_id}/icon` (грузит интерфейс,
  кэш на диске в `.forge/icons`; в тестах сеть выключена `FORGE_NO_ICON_NET=1`).

## Язык интерфейса

`[ui] lang` (`ru`/`en`), переключатель RUS/ENG в шапке пульта. Русский — исходный: строки в коде
русские и служат ключами, `tr("…", name=…)` переводит при показе, `N_("…")` — для констант,
`plural()` — числительные; английский — словари `forge/i18n/en_*.py`. `tests/test_i18n.py` ловит
русскую строку мимо `tr()` и ключ без перевода. CLI — только русский.

## Модель логистики (по умолчанию)

Три места — все настраиваются (`[locations]`, «Настройки → Места логистики»); по умолчанию:

- **стройка** (`gplb_c`) — система с Engineering Complex (производство) и Refinery (реакции);
- **хаб закупки** (`jita`) — Jita IV - Moon 4, регион The Forge;
- **рынок сбыта / 2-й хаб** (`c_j6mt`) — рынок-структура (C-J6MT), тут же можно и закупать.

```
Jita ──ISK/m³──▶ рынок сбыта ──рейсы/фикс──▶ стройка ──рейсы/фикс──▶ рынок сбыта
                 закупка                     стройка                 продажа
```

- Себестоимость материала = min(
  наличие на складе по цене замещения;
  цена рынка сбыта + фрахт(рынок сбыта → стройка);
  цена Jita + фрахт(Jita → рынок сбыта) + фрахт(рынок сбыта → стройка) ).
- Выручка = цена на рынке сбыта − налог и брокер структуры − вывоз(стройка → рынок сбыта).
- Фрахт — два режима маршрута (`config.FreightRoute.mode`, считается в `core/cost.py`):
  - `per_m3` — линейно: `isk_per_m3 × объём`, но не меньше `min_cost` за заказ, если он задан.
    Минимум считается РАЗ на весь заказ (батчево, тем же механизмом, что и рейсы `fixed_jump`),
    не на каждый материал по отдельности.
  - `fixed_jump` — РЕЙСАМИ, не линейно (`route_freight_cost`/`jump_freight_cost`): 1-я партия
    (влезает в `vessel_capacity_m3 × load_factor`) — один прыжок (`fixed_cost`); каждая
    ДОПОЛНИТЕЛЬНАЯ партия — ещё два прыжка (порожняком назад + снова с грузом). N партий за
    один заказ ⇒ `(2N − 1) × fixed_cost`. Объём считается ПО ВСЕМУ ЗАКАЗУ разом —
    `core.estimate_basket`/`core.batched_freight_params` суммируют объём по плечу со всех
    деревьев и выводят единую эффективную ставку; отчёт (`report.py`) считает реальную стоимость
    рейса напрямую от факт-объёма закупки (после вычета склада) через `route_freight_cost`.
  - Капиталы (`jump_capable_groups`) при вывозе — исключение: летят своим ходом, в трюм не
    грузятся → фикс `fixed_cost` топлива ЗА ШТУКУ, без деления на партии (`jump_fuel`).
- Всё это — настройки: имена/системы мест (`[locations]`), хабы закупки и цена продажи
  (`[market]`), склад (`[stock]`: авто или выбранные системы/локации; остатки из хабов довозятся
  тем же фрахтом), «всегда покупать/строить», запреты рекомендаций, роли персонажей (в т.ч.
  «наука»), учёт запущенных джобов (`[planner]`). Полный справочник — `forge.example.toml`.

Известные ID: Jita system `30000142`, The Forge region `10000002`. Остальные системы/регионы
резолвятся из SDE по имени.

## Формула стоимости (локально)

- Стоимость установки джоба от EIV: `adjusted_price` (таблица `market_adjusted_prices`) ×
  system cost index (`system_cost_indices`) × бонусы структуры и ригов (`facilities`) ×
  `(1 + facility_tax + SCC_surcharge)`.
- Количество материала на джоб: `max(runs, ceil(base × runs × (1 − ME/100) × структура × риги))`.
  Реакции ME игнорируют.

## Конвенции

- Тесты на каждый модуль; ESI/Fuzzwork в тестах мокать (`httpx.MockTransport`), живые вызовы не делать.
- Перед коммитом зелёные: `pytest`, `ruff check forge tests`, `mypy forge`.
- Тесты пульта (`tests/test_desktop*.py`) создают окна без экрана (`QT_QPA_PLATFORM=offscreen`)
  и без сети (`FORGE_NO_ICON_NET=1`); без PySide6 пропускаются.
- ESI base `https://esi.evetech.net`, docs `https://docs.esi.evetech.net`. SDE — SQLite-дамп Fuzzwork.

## Глоссарий

- BPO / BPC — оригинал / копия чертежа; ME / TE — material / time efficiency; runs — число прогонов.
- EIV — Estimated Item Value (база стоимости джоба, из adjusted_price, НЕ рыночная цена).
- landed cost — цена материала с учётом доставки до места стройки.
- поток (stream) — один параллельный джоб; «5 потоков × 3 дня» = 5 параллельных джобов.
