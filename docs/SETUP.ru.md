# Настройка Forge — пошаговая инструкция

[English](SETUP.md) · **Русский** · [← README](../README.ru.md)

Эта инструкция ведёт от распакованного архива до первого точного расчёта: SDE, персонажи, ваши
места (где покупаете, строите, продаёте), станции с ригами, фрахт, роли персонажей, чертежи и
склад. Все кнопки и поля описаны так, как они называются в программе. Справочник по всем
вкладкам и опциям — в [README](../README.ru.md#программа-по-вкладкам).

Первая настройка занимает 20–40 минут. Большую часть времени программа сама качает данные.

## 1. Что понадобится

- Windows 10 или 11 и около 1 ГБ на диске (база игры и ваши данные).
- Доступ к аккаунтам EVE, персонажей которых вы хотите добавить: вход идёт через официальную
  страницу EVE Online, пароль в Forge не вводится.
- Решите заранее (можно поменять потом):
  - **где покупаете** материалы (обычно Jita);
  - **где продаёте** продукцию: в том же хабе или на рынке-структуре (кипстар альянса и т.п.);
  - **где строите**: система, где стоят ваши (или доступные вам) Engineering Complex и Refinery;
  - сколько стоит доставка между этими местами.

ID структур знать заранее не нужно — Forge сам покажет их после синхронизации персонажей
([раздел 8](#8-структуры-склада-и-рынки-структуры)).

## 2. Установка и запуск

### Переносная сборка (рекомендуется)

1. Скачайте `Forge_<версия>.zip` со страницы [Releases](https://github.com/ogamekuz/Forge/releases).
2. Распакуйте архив **целиком** в любую папку, куда у вас есть права на запись: Рабочий стол,
   Документы, `D:\Games\Forge`… Права администратора не нужны. Не запускайте программу прямо из
   архива: без распаковки она не найдёт свой Python.
3. Дважды кликните `Forge.cmd`.
4. Если Windows покажет «Windows защитил ваш компьютер», нажмите «Подробнее», затем «Выполнить в
   любом случае». У программы нет цифровой подписи, поэтому Windows и предупреждает.
5. Если брандмауэр спросит про `pythonw.exe`, разрешите доступ. Это встроенный сервер отчётов, он
   слушает только `127.0.0.1` и снаружи недоступен.

В переносной сборке уже прописано приложение EVE SSO (Client ID), регистрировать своё не нужно.

### Из исходников

Подробно — в [README](../README.ru.md#из-исходников). Коротко: Python 3.12+, `pip install -e
".[dev,desktop]"`, `copy forge.example.toml forge.toml`. Затем зарегистрируйте своё приложение на
<https://developers.eveonline.com/>:

- *Connection type* — **Authentication & API Access**;
- *Callback URL* — `http://localhost:8765/callback`;
- *Scopes* — семь скоупов из таблицы в [разделе 4](#4-персонажи-eve-sso).

Скопируйте **Client ID** приложения в «Настройки → Система → EVE SSO» и нажмите **Сохранить**.
Секретный ключ (Secret Key) не нужен: Forge входит по OAuth2 PKCE.

### Язык

Переключатель **RUS / ENG** — в шапке окна. Язык меняется сразу; новые HTML-отчёты пишутся на
выбранном языке.

## 3. Статические данные игры (SDE)

SDE — справочник игры: предметы, чертежи, риги, системы. Без него не работают ни поиск, ни расчёты.

1. Вкладка **Обзор** → карточка **Синхронизация** → **Скачать SDE** → **Скачать**.
2. Дождитесь «Синк завершён.». Это несколько минут: дамп с Fuzzwork весит сотни мегабайт.
3. Прогресс и итог видны в карточке **Источники данных** (строка «SDE (Fuzzwork)»).

Повторять нужно только после крупных патчей игры (новые предметы, чертежи, риги).

## 4. Персонажи (EVE SSO)

Forge видит слоты, скиллы, чертежи, ассеты и идущие джобы только тех персонажей, которых вы
добавили. Джобы идут и оффлайн, поэтому имеет смысл добавить **всех** персонажей, которые
занимаются индустрией, со всех аккаунтов.

### Добавление персонажа

1. **Обзор → Добавить персонажа (EVE SSO)**. В браузере по умолчанию откроется официальная
   страница входа EVE Online (`login.eveonline.com`).
2. Войдите в аккаунт и **выберите персонажа** в списке.
3. Проверьте список разрешений (все только на чтение, см. таблицу ниже) и нажмите **Authorize**.
4. Браузер покажет «Forge: авторизация получена.». Вкладку можно закрыть.
5. В Forge появится «Добавлен: <имя>».
6. Повторите для каждого персонажа: по одному входу на персонажа.

Советы:

- **Персонаж с другого аккаунта.** Если страница EVE сразу предлагает персонажей уже вошедшего
  аккаунта, выйдите из аккаунта на этой странице (сменить аккаунт) и войдите нужным.
- **Время на вход — 5 минут.** Не успели — нажмите кнопку ещё раз.
- Повторный вход тем же персонажем безопасен: запись и доступ просто обновятся.

### Какие права запрашивает Forge

Все скоупы только на чтение: Forge ничего не меняет в игре и не двигает ISK.

| Скоуп | Зачем |
|---|---|
| `esi-characters.read_blueprints.v1` | ваши чертежи: ME/TE, раны, где лежат |
| `esi-skills.read_skills.v1` | скиллы: число слотов, время джобов, шанс инвенты |
| `esi-assets.read_assets.v1` | ассеты: склад и где лежат чертежи |
| `esi-industry.read_character_jobs.v1` | идущие джобы: занятые слоты в расписании |
| `esi-wallet.read_character_wallet.v1` | баланс кошелька (карточки «Обзора» и «Персонажей») |
| `esi-markets.structure_markets.v1` | ордера рынков-структур (цены рынка сбыта) |
| `esi-universe.read_structures.v1` | имена и системы структур (склад, станции) |

### Где хранится доступ

Forge хранит не пароль, а refresh-токен EVE. Токены лежат в **Диспетчере учётных данных
Windows** — не в базе и не в `forge.toml`. Если EVE перестаёт принимать сохранённый вход (смена
пароля, отзыв доступа на сайте EVE, перенос персонажа), в «Обзоре» и на вкладке «Персонажи»
появится «нужен вход». Тогда снова **Добавить персонажа (EVE SSO)** этим персонажем.

## 5. Синхронизация данных

Карточка **Синхронизация** на «Обзоре» — единственное место, где Forge ходит в сеть.

1. **Персонажи + рынки структур** — чертежи, скиллы, ассеты, джобы и кошельки всех персонажей;
   имена и системы структур; ордера рынков-структур из настроек. Занимает от нескольких секунд до
   пары минут.
2. **Рынок Jita и индексы** — цены хаба закупки, adjusted prices (база стоимости джобов),
   индексы стоимости систем, история рынка. Первый раз — до 10–15 минут (качается история),
   дальше быстрее: история обновляется раз в сутки.

Проверка: вкладка **Персонажи** — у каждого персонажа есть слоты, чертежи, ассеты и время
обновления. Синк уважает кэш ESI, поэтому повторный запуск сразу после предыдущего может ничего
не докачать — это нормально.

> Персонажей и рынок полезно синхронизировать **после** настройки мест и структур
> (разделы 6–8): тогда подтянутся имена структур и ордера рынков-структур.

## 6. Места: где покупаете, строите и продаёте

**Настройки → Логистика и рынок → Места.** Это самая важная настройка: от неё зависят цены
закупки, цены продажи, индекс стоимости джобов и фрахт.

```
 Хаб закупки ──фрахт──▶ Рынок сбыта / 2-й хаб ──фрахт──▶ Место стройки ──фрахт──▶ Рынок сбыта
 (обычно Jita)          (тоже можно закупать)           (ваши EC и Refinery)      (продажа)
```

| Роль | Что это | Откуда цены |
|---|---|---|
| **Хаб закупки** | где покупаете материалы | агрегаты рынка региона хаба (Fuzzwork) |
| **Рынок сбыта / 2-й хаб** | где продаёте продукцию (и тоже можете закупать) | ордера рынков-структур из настроек; если рынок сбыта в том же регионе, что хаб закупки, — цены хаба |
| **Место стройки** | система, где идут джобы | индекс стоимости этой системы (если у станции не указана своя) |

Как поменять место:

1. В строке роли нажмите поле **«сменить систему…»**, начните вводить название системы и выберите
   её из списка. Регион подставится сам.
2. Впишите в поле слева **название**, которое хотите видеть в отчётах. Название само подставится,
   только если поле пустое — **старое название при смене системы не меняется**, исправьте его
   вручную.
3. **Сохранить** (кнопка вверху страницы настроек).

Типовые варианты:

| Ваш случай | Хаб закупки | Рынок сбыта / 2-й хаб | Место стройки | Рынки-структуры |
|---|---|---|---|---|
| Хайсек: покупаю и продаю в Jita | Jita | **Jita** | ваша система | не нужны |
| Нули: покупаю в Jita, продаю на кипстаре | Jita | система кипстара | система ваших EC/Refinery | кипстар (и другие рынки той системы) |
| Строю и продаю в одной системе с рынком | Jita | система стройки | система стройки | рынок-структура этой системы |

> ⚠ **Цены продажи.** Forge берёт цены рынка сбыта из ордеров **рынков-структур**
> ([раздел 8](#8-структуры-склада-и-рынки-структуры)), а если рынок сбыта в том же регионе, что
> хаб закупки, — из цен хаба. NPC-хаб в другом регионе (Amarr, Dodixie, Rens, Hek) как рынок
> сбыта Forge не скачивает. Если в «Калькуляторе» у продукции нет цены продажи и прибыли,
> почти всегда дело здесь: поставьте рынком сбыта систему хаба закупки (Jita) или добавьте
> рынок-структуру.

Без своих станций Forge тоже считает: просто без бонусов структур и с индексом стоимости
системы стройки.

## 7. Станции и риги («станки»)

**Настройки → Станции.** Здесь описываются структуры, в которых вы запускаете джобы: их тип, риги,
налог и какие продукты туда идут. От этого зависят расход материалов (ME-бонус), время джобов и
стоимость установки.

### Как Forge выбирает станцию для джоба

1. По **виду джоба** определяется роль: реакция → «реакции», инвента → «инвента», копирование →
   «копирование», производство → «производство».
2. Для производства сначала ищется станция роли **«T2-компоненты (по группам)»**, у которой в
   списке есть группа или категория продукта.
3. Затем станция нужной роли, у которой в «Какие продукты сюда» есть **группа или категория
   продукта**.
4. Затем станция нужной роли с **пустым** «Какие продукты сюда» — «для всего остального».
5. Если подходящей станции нет — запасные множители из «Настройки → Производство» (по умолчанию
   без бонусов).

Станция с группами или категориями всегда важнее станции «для всего». Порядок карточек важен,
только если две карточки одной роли претендуют на один и тот же продукт: тогда берётся верхняя.

### Роли

| Роль в Forge | Какие джобы | Типичная структура |
|---|---|---|
| производство (остальное) | всё производство, не попавшее в другие станции | Raitaru / Azbel / Sotiyo |
| T2-компоненты (по группам) | производство только перечисленных групп (обязательно укажите группы) | EC с ригами Advanced Component |
| реакции | реакции | Athanor / Tatara |
| инвента | инвента T2/T3 | EC с ригами Invention |
| копирование | копирование чертежей (для инвенты) | Engineering Complex |

Размер ригов должен подходить структуре: **M-Set** — Raitaru и Athanor, **L-Set** — Azbel и Tatara,
**XL-Set** — Sotiyo.

### Добавление станции

1. **Добавить станцию**. Появится карточка «Новая станция».
2. **Название** — любое, для себя и отчётов. Например: «Sotiyo — корабли».
3. **Роль** — выпадающий список справа от названия.
4. **Где стоит** — структура в игре. В списке — все станции и структуры, где у ваших персонажей
   лежат ассеты (после синка персонажей), в виде «Название · id». Если нужной нет — положите в неё
   любой предмет и синхронизируйте персонажей, или впишите id вручную. Поле нужно для подписей,
   склада и автоопределения системы.
5. **Система** — по умолчанию «авто»: система структуры из «Где стоит» (а если она ещё не
   известна — система стройки). От системы зависят **индекс стоимости** джобов станции и **бонус
   ригов**: в low-sec и null-sec риги дают больше, Forge учитывает это сам. Выбрать вручную — поле
   «Выбрать систему станции вручную…»; сбросить на авто — крестик.
6. **Тип структуры** — найдите Raitaru, Azbel, Sotiyo, Athanor или Tatara. Встроенные бонусы
   структуры (у Engineering Complex — материалы, время и стоимость; у Tatara — время реакций)
   берутся из SDE.
7. **Риги и сервис-модули** — найдите каждый риг по названию (например, `Standup M-Set Equipment
   Manufacturing Material Efficiency I`) и добавьте. Бонусы считаются из SDE со стэкинг-пенальти.
8. **Налог станции, %** — налог владельца структуры **в процентах**: `1` = 1%, `0.5` = 0,5%.
9. **Какие продукты сюда** — EVE-группы и/или EVE-категории продуктов. Пусто — станция берёт все
   продукты своей роли, которые не забрали более точные станции.
10. **Сохранить**. После сохранения под ригами появится строка **«Расчётный бонус (по
    сохранённому фиту): материалы …%, время …%, стоим. джоба …%»** — так видно, что риги
    распознаны.

Поля «ME эконом., %», «Время эконом., %», «Стоим. джоба эконом., %» нужны, **только если не
указаны ни тип структуры, ни риги**: например, если структура чужая и вы знаете лишь итоговые
бонусы. Как только указан тип или хоть один риг, ручные проценты не используются.

### Главное правило: одна карточка — один набор ригов

Риги карточки действуют на **все** продукты, которые попали в эту карточку. В игре же каждый риг
действует только на свои типы продуктов. Поэтому, если на одной структуре стоят риги под разные
продукты, заведите на неё **несколько карточек** — по одной на каждый риг (или набор ригов на одни
и те же продукты) — и в каждой укажите в «Какие продукты сюда» группы или категории, на которые
действует риг. На что действует риг, видно в игре: Show Info рига.

Плюс одна карточка «для всего остального» — без групп, без ригов, но с типом структуры: так
остальные продукты получат хотя бы встроенный бонус структуры.

### Примеры

**Один Raitaru без ригов, всё строится там.** Одна карточка: роль «производство (остальное)»,
«Где стоит» — ваш Raitaru, тип структуры Raitaru, налог станции, «Какие продукты сюда» пусто.

**Sotiyo с XL-ригом на корабли.**

| Карточка | Роль | Тип | Риги | Какие продукты сюда |
|---|---|---|---|---|
| Sotiyo — корабли | производство | Sotiyo | Standup XL-Set Ship Manufacturing Efficiency I | категория **Ship** |
| Sotiyo — остальное | производство | Sotiyo | — | пусто |

**Raitaru: модули и T2-компоненты.**

| Карточка | Роль | Тип | Риги | Какие продукты сюда |
|---|---|---|---|---|
| Raitaru — модули | производство | Raitaru | Standup M-Set Equipment Manufacturing Material Efficiency I, Standup M-Set Equipment Manufacturing Time Efficiency I | категория **Module** |
| Raitaru — T2-компоненты | T2-компоненты (по группам) | Raitaru | Standup M-Set Advanced Component Manufacturing Material Efficiency I | группа **Construction Components** |
| Raitaru — остальное | производство | Raitaru | — | пусто |

**Реакции на Athanor.** M-Set риги реакторов разделены по видам реакций, поэтому — по карточке на
каждый:

| Карточка | Роль | Тип | Риги | Какие продукты сюда |
|---|---|---|---|---|
| Athanor — композиты | реакции | Athanor | Standup M-Set Composite Reactor Material Efficiency I | группы **Intermediate Materials**, **Composite** |
| Athanor — полимеры | реакции | Athanor | Standup M-Set Hybrid Reactor Material Efficiency I | группа **Hybrid Polymers** |
| Athanor — биохимия | реакции | Athanor | Standup M-Set Biochemical Reactor Material Efficiency I | группа **Biochemical Material** |

**Реакции на Tatara.** L-Set риг `Standup L-Set Reactor Efficiency I` действует на все реакции,
поэтому хватит одной карточки: роль «реакции», тип Tatara, этот риг, «Какие продукты сюда» пусто.

**Инвента и копирование.** Карточка с ролью «инвента» (например, Raitaru с
`Standup M-Set Invention Cost Optimization I` и/или `Standup M-Set Invention Accelerator I`) и, при
желании, карточка «копирование». Без них инвента и копирование считаются по запасным множителям и
индексу системы стройки.

### Если станция в другой системе

Станция может стоять не в системе стройки: укажите её «Где стоит» или выберите систему вручную —
индекс стоимости и бонусы ригов посчитаются по её системе. Перевозку материалов между системами
Forge **не** считает: материалы считаются доставленными в систему стройки.

## 8. Структуры склада и рынки-структуры

### Как узнать id структуры

- **Склад → Где что лежит**: наведите курсор на станцию или структуру — подсказка покажет
  «Название · id …».
- **Настройки → Станции → Где стоит**: список «Название · id».
- Если структуры нет ни там, ни там — у ваших персонажей в ней нет ассетов. Положите туда любой
  предмет (хоть 1 Tritanium) и нажмите **Персонажи + рынки структур**.

Имя и систему структуры игрока Forge узнаёт через ESI, и только если у кого-то из персонажей есть
к ней доступ (докинг). Иначе структура видна как «Структура <id>», а её система — неизвестна.

### Структуры места стройки

**Настройки → Логистика и рынок → Структуры:**

- **Engineering Complex места стройки** и **Refinery места стройки** — id ваших структур стройки.
  Склад в режиме «Авто» считает «уже есть» то, что лежит в них (и в локациях «Где искать
  чертежи»).
- **Рынок-структура по умолчанию** — id рынка; используется, только если список «Рынки-структуры»
  ниже пуст.

### Рынки-структуры

**Настройки → Логистика и рынок → Рынки-структуры** — откуда брать цены рынка сбыта.

1. Выберите структуру в списке **«— известная структура —»** и нажмите **Добавить** — или впишите
   id в поле «id структуры» и нажмите **По id**.
2. **Сохранить**, затем **Обзор → Персонажи + рынки структур**.
3. Проверьте **Обзор → Источники данных → «Рынки-структуры»**: итог по каждой структуре.

Ордера всех перечисленных структур сводятся в **один** срез рынка сбыта: минимальный sell,
максимальный buy, суммарный объём. Каждую структуру скачивает персонаж с доступом к её рынку:
сначала тот, у кого там лежат ассеты; нет доступа — пробуется следующий. Ошибка одной структуры
не мешает остальным. Пометка «⚠ не в системе хаба» значит, что структура не в системе рынка
сбыта: её ордера всё равно попадут в срез — уберите её, если это не то, что нужно.

## 9. Налоги, рынок и фрахт

### Налоги

**Настройки → Производство → Производство и налоги.** Здесь значения — **доли**, не проценты:
`0.01` = 1%.

| Поле | Что вписать |
|---|---|
| SCC surcharge, доля | налог SCC на установку джобов, `0.04` (4%) |
| Брокер при продаже, доля | брокерская комиссия на рынке сбыта |
| Налог с продажи, доля | sales tax с учётом ваших скиллов |
| Налог структуры, доля (фолбэк) | налог для джобов, под которые нет станции |
| Множители материалов, стоимости, времени (фолбэк) | `1.0` — без бонуса; действуют, только если под роль джоба нет станции |
| Эффективность переработки | `0` — не рассматривать переработку; иначе ваша доля, например `0.85` |

Брокер и налог с продажи по умолчанию — `0`: без них прибыль завышена. Точные значения видны в
игре в окне выставления sell-ордера на вашем рынке сбыта.

### Где покупать и как считать продажу

**Логистика и рынок → Рынок:**

- **Покупать в <хаб> (+ доставка)** и **Покупать в <рынок сбыта>**. Обе галки выключены — то же,
  что обе включены. Forge берёт самый дешёвый вариант с доставкой и учитывает, сколько товара
  реально выставлено.
- **Продажа: выставить sell-ордер** (по минимальному sell) или **Продажа: сразу в buy-ордер** (по
  максимальному buy).

### Фрахт

**Логистика и рынок → Фрахт (плечи логистики)** — три плеча: хаб → рынок сбыта, рынок сбыта →
стройка, стройка → рынок сбыта. Плечо с нулями — бесплатная доставка (например, если хаб и рынок
сбыта — одна система).

Два режима:

- **per_m3** — оплата за объём, как у курьерских сервисов. *ISK/м³* — ставка, *мин. за заказ* —
  минимальная цена одного заказа. Минимум считается **один раз на весь заказ**, а не на каждый
  материал. Пример: 800 ISK/м³, минимум 5 000 000 ISK.
- **рейсами** (fixed_jump) — свой джамп-фрейтер или фиксированная цена рейса. *ISK за прыжок* —
  стоимость одного рейса в одну сторону (топливо или цена перевозчика), *вместимость, м³* — трюм
  корабля, *загрузка 0–1* — какую долю трюма реально заполняете (например, `0.9`). Первая партия —
  один рейс; каждая следующая — ещё два (назад порожняком и снова с грузом): N партий = 2N − 1
  рейсов. Объём суммируется по всему заказу.

**Самоходные при вывозе** — группы кораблей (джамп-фрейтеры, карриеры, дредноуты, титаны…),
которые летят на рынок своим ходом. Их вывоз считается как «ISK за прыжок» плеча «стройка →
рынок» за штуку, а не по объёму. Список по умолчанию уже заполнен.

## 10. Роли персонажей и лимиты слотов

Вкладка **Персонажи**:

- **Произв.**, **Реакции**, **Наука** — кто какие джобы может запускать в расписании. «Наука» —
  инвента и копирование.
  - Ни одной галки ни у кого — все персонажи участвуют во всём.
  - Как только отмечена хоть одна галка, в каждом пуле участвуют **только отмеченные в нём**.
    Строите реакции — отметьте кого-то в колонке «Реакции»: если она пустая, а другие колонки
    заполнены, реакции ставить некому.
  - Исключение — «Наука»: пустая колонка значит, что науку делают те, кто отмечен в «Произв.».
  - Персонаж без галок (когда у других они есть) в стройке не участвует.
- **Лимит Forge пр/рк/нк** — сколько слотов расписание может занять у этого персонажа. Пусто — все
  слоты по скиллам; `0` — персонаж в этом пуле не участвует. Так можно оставить слоты под ресёрч и
  свои джобы. Уже идущие джобы занимают слоты до окончания.
- **Сохранить роли**.

Число слотов Forge считает по скиллам персонажа. Колонка «Обновлён» показывает, когда данные
персонажа синхронизировались последний раз; «нужен вход» — см. [раздел 4](#где-хранится-доступ).

## 11. Чертежи

**Настройки → Чертежи:**

- **Где искать чертежи** — список локаций, где у персонажей лежат чертежи, с их числом. Отметьте
  те, где лежат рабочие чертежи: «своими» будут считаться только они (и чертежи в контейнерах
  внутри). Ничего не отмечено — свои все чертежи. Влияет на ME/TE в расчётах, стоимость чертежа,
  ТОП «Только свои чертежи» и то, кому расписание отдаёт джоб. Список появляется после синка
  персонажей.
- **Стоимость чертежей вручную (ISK на 1 прогон)** — для чертежей, которых у вас нет и которые
  нельзя заинвентить (например, покупные копии). Для T1-чертежа инвенты — цена одной T1-копии на
  попытку.

Forge читает **чертежи персонажей**. Чертежи корпорации (в корпоративных ангарах) он не видит.
Для них задайте ME/TE в корзине «Калькулятора» (поле ME у строки) или значения по умолчанию:
«Настройки → Планировщик → Корзина по умолчанию → ME, если нет своего чертежа» (и TE).

## 12. Склад

Вкладка **Склад** решает, что считается «уже есть» и не покупается заново.

- **Авто** — структуры стройки из [раздела 8](#структуры-места-стройки) плюс локации «Где искать
  чертежи». Если структуры стройки не указаны, «Авто» почти ничего не найдёт.
- **Выбрать вручную** — галки в дереве «Где что лежит»: система целиком (вместе с будущими
  структурами в ней), отдельная станция, структура или контейнер. Снятая галка внутри отмеченной
  системы — исключение. Кнопка **Взять выбор «Авто» за основу** — начать с того, что выбрал
  «Авто».
- **Фильтры** — чьи ассеты считать; не считать складом модули в фите, собранные корабли и
  предметы в трюме, дронбее, Asset Safety и т.п. Отсечённое дерево показывает серым «не склад».
- **Запреты и запас** — что никогда не брать со склада и сколько штук не трогать.
- **Сохранить склад**. Итог — в карточке **Сейчас на складе**.

Остатки вне места стройки тоже идут в дело: из хаба и рынка сбыта отчёт довозит их тем же
фрахтом, остальные системы помечает.

## 13. Инвента, «всегда покупать / строить», планировщик

Можно оставить по умолчанию и вернуться позже.

- **Настройки → Производство → Инвента** — шанс со скиллами инвентора (лучший из роли «Наука») и
  выбор декриптора: «Авто — по стоимости», «Без декриптора», «Один для всех», плюс декриптор для
  конкретных T2-товаров.
- **Всегда покупать / Всегда строить** — группы или предметы. Типичный пример: группа **Fuel
  Block** — всегда покупать.
- **Настройки → Планировщик** — учитывать ли запущенные джобы, ставить ли копирование T1-чертежей
  в расписание, кому ставить джоб (любому / предпочитать владельца чертежа / только владельцу),
  варианты сроков для «Сравнить варианты», значения корзины по умолчанию.
- **Настройки → Рекомендации** — веса и фильтры вкладки «Что строить», запреты, группы ТОП.

## 14. Автообновление

**Обзор → Автообновление**: «Обновлять в фоне, пока открыт пульт», интервалы для рынка (по
умолчанию 30 минут) и персонажей (60 минут) → **Сохранить**. Синк срабатывает, когда с последнего
успешного прошло больше интервала.

## 15. Проверка: первый расчёт

1. **Калькулятор** → найдите предмет, который вы строите, → в строке корзины укажите прогоны →
   **Посчитать корзину**.
2. **Подготовка / проблемы** — чего не хватает: чертежей, копий формул, рыночных цен.
3. **По предметам → Установка джоба (основной чертёж) — разбивка** — строки «× индекс системы
   <система>», «× множитель станции», «+ налог + SCC». Убедитесь, что система — та, где стоит
   станция, а множитель станции не `×1.000` (если на станции есть бонус к стоимости).
4. Блок **Материалы** (дерево) — количество, цена в каждом хабе, источник (строить / купить /
   склад). Клик по источнику переключает «строить ↔ купить».
5. Есть цена продажи и прибыль? Если нет — [раздел 6](#6-места-где-покупаете-строите-и-продаёте).
6. **Расписание → Построить расписание** — джобы разложены по слотам ваших персонажей.
7. **Сформировать отчёт по стройке** — откроется HTML-отчёт: список закупок, инструкции по
   персонажам, контроль сроков и стоимости.

## 16. Обновление, перенос и резервная копия

Все ваши данные лежат в папке программы:

| Файл / папка | Что это |
|---|---|
| `forge.toml` | настройки |
| `forge.db` | база: SDE, рынок, персонажи, склад |
| `reports/` | отчёты по стройкам и внесённые в них факты |
| `.forge/` | состояние окна, корзина, кэш иконок |
| `forge_desktop.log` | журнал ошибок |

- **Новая версия:** распакуйте её в новую папку и перенесите туда `forge.toml`, `forge.db` и
  `reports/`. Персонажей добавлять заново не нужно.
- **Другой компьютер:** скопируйте папку целиком, затем снова добавьте персонажей: их доступ хранится
  в Диспетчере учётных данных Windows, а не в папке.
- **Резервная копия:** `forge.toml`, `forge.db` и `reports/`. Самое ценное — `forge.toml` (ваши
  настройки) и `reports/` (стройки и внесённые в них факты); данные в `forge.db` можно скачать
  заново, но тогда придётся снова добавить персонажей и ждать SDE и историю рынка.

## 17. Если что-то не так

| Симптом | Что сделать |
|---|---|
| Нет цены продажи и прибыли | Рынок сбыта — NPC-хаб другого региона или рынок-структура не добавлена / недоступна. См. [раздел 6](#6-места-где-покупаете-строите-и-продаёте) и [раздел 8](#рынки-структуры). |
| «Не задан sso.client_id в конфиге.» | Установка из исходников: впишите Client ID своего приложения в «Настройки → Система». |
| «Не дождались ответа SSO на callback.» | Вход занял больше 5 минут, порт 8765 занят, или Callback URL приложения не совпадает с «Порт callback» в «Настройки → Система». |
| «Нужно войти заново» / «нужен вход» | **Добавить персонажа (EVE SSO)** этим персонажем, затем **Персонажи + рынки структур**. |
| Структура видна как «Структура <id>» | Ни у кого из персонажей нет к ней доступа (докинг) или синк персонажей ещё не запускался. |
| Ошибка доступа у рынка-структуры | У персонажей нет доступа к её рынку. Итог по каждой структуре — «Обзор → Источники данных». |
| Нет строки «Расчётный бонус» у станции | Не выбраны ни тип структуры, ни риги, или настройки не сохранены. |
| Бонус рига действует не на те продукты | Разнесите риги по карточкам и укажите группы или категории ([раздел 7](#главное-правило-одна-карточка--один-набор-ригов)). |
| Реакции или инвента не попадают в расписание | В «Персонажах» отмечены роли, но колонка «Реакции» (или «Наука» вместе с «Произв.») пустая ([раздел 10](#10-роли-персонажей-и-лимиты-слотов)). |
| Склад «Авто» пустой | Не указаны структуры стройки ([раздел 8](#структуры-места-стройки)) — или переключитесь на «Выбрать вручную». |
| Forge не видит чертёж | Чертёж в корпоративном ангаре или вне отмеченных «Где искать чертежи». |
| Отчёты не открываются | Заняты все порты 8000–8010; остальная программа работает. |
| Окно не открывается | Смотрите `forge_desktop.log` в папке программы. |

## 18. Файл forge.toml вручную

Всё из этой инструкции хранится в `forge.toml` рядом с программой. Пульт переписывает его при
сохранении и комментарии не сохраняет. Справочник с пояснениями ко всем ключам —
[forge.example.toml](../forge.example.toml).

Ключи мест — это идентификаторы ролей, а не названия систем:

| Роль в пульте | Ключ в `forge.toml` |
|---|---|
| Хаб закупки | `[locations.jita]` |
| Рынок сбыта / 2-й хаб | `[locations.c_j6mt]` |
| Место стройки | `[locations.gplb_c]` |
| Рынок-структура по умолчанию | `[structures] taj_mahgoon_market_id` |
| Engineering Complex места стройки | `[structures] gplb_engineering_complex_id` |
| Refinery места стройки | `[structures] gplb_refinery_id` |
| Рынки-структуры | `[structures] market_structures` |
| Станции | `[[facilities]]` |
| Фрахт | `[[freight_routes]]` (`from`/`to` — ключи мест выше) |

Ключи верхнего уровня (роли персонажей, «Где искать чертежи», «всегда покупать / строить»)
пишутся **до** первой `[секции]`, иначе TOML отнесёт их к ней.
